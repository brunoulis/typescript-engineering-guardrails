# Sandboxed deno-test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in `deno-test` integration that runs a Deno project's unit tests inside a read-only snapshot with the narrowest permissions, classifies each failure as `permission`, `environment` or `assertion`, and reports the result as `DENO_TEST_FAILURE` findings plus a one-line summary.

**Architecture:** `deno-junit.ts` parses the JUnit XML that `deno test --reporter=junit --junit-path` writes (pure, fail-closed). `deno-test.ts` builds the sandboxed command and turns cases into findings. It plugs into the existing Deno integration set in `deno-tools.ts` (same snapshot, same `INCOMPLETE`-on-any-failure contract). The sandbox is fixed: snapshot-only read, **network always denied**, a scrubbed child environment, and no subprocess or FFI permission at all.

**Tech Stack:** TypeScript 6.0.3 (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), Node ≥22.13 `node:test`, Deno 2.9.8 on `PATH`.

**Spec:** `docs/superpowers/specs/2026-11-17-deno-oracle-integrations-design.md` (section 1, `deno-test` row). **Prerequisites:** Plans A and B committed in `main`.

## Scope, evidence and decisions

**Machine-load policy (read first).** An earlier session froze the workstation while a full test run and several builds ran together. Here: run test files **one at a time** with `timeout`, never `npm run verify`, never the corpus or runtime-project tests, never two builds at once, nothing in the background, subagents **sequentially**.

This is **Plan C of three** (A = Deno integrations, B = Oracle checks).

Running a project's tests is running its code, so this integration is opt-in (`--integration deno-test`) and deliberately conservative. Measured on a private Deno + Oracle backend (183 test cases in 40 files, snapshot without `.env`, Deno 2.9.8, Windows):

| Permissions granted | Passed | Failed | Failure classes |
| --- | --- | --- | --- |
| snapshot read only (default) | 172 | 11 | 11 permission (env variables the tests read) |
| plus `env`, `sys` | 179 (+1 skipped) | 6 | 4 permission (3 need a subprocess, 1 needs the network), 2 environment (`NJS-045`: the native Oracle client cannot load without FFI) |
| assertion failures | — | 0 in both runs | — |

So the sandbox is informative (no real assertion failure in the project) without touching any real system. One file the project runs as a `deno run` task against real Oracle was excluded from the run by the "script-like" rule below; without it the sandbox would be the only thing standing between that file and a real database.

Decisions assumed (change them before executing if you disagree):

1. **No network, ever.** There is no way to request it. Thick-mode Oracle talks through the native client over FFI, which is not offered either, so the two refusals together keep tests away from real databases.
2. **Only `env`, `sys`, `write` can be granted** (`--deno-test-allow env,sys,write`, or `denoTestAllow` in config). `write` is limited to the snapshot (`--allow-write=.`). `run` and `ffi` are not offered: those tests stay `permission`/`environment` findings and the report says so. A test that needs them should be run by the owner after reading its runner.
3. **The child environment is scrubbed** to the variables Deno needs to start (`PATH`, `HOME`/`USERPROFILE`, `LOCALAPPDATA`, `TEMP`, `DENO_DIR`, …). Even with `env` granted, project secrets in the caller's environment stay invisible.
4. **Scripts are not tests.** A file named by a `deno.json` task that runs `deno run` is excluded even if it matches Deno's test-file pattern.
5. **Messages are redacted** (snapshot path → `<snapshot>`, home directory → `~`) and cut to the first line (200 characters); stack traces are never recorded.
6. **Severity:** assertion/runtime failures P2, permission and environment failures P3, all `HEURISTIC` (same decision as Plan A). `integrations[].summary` is a new optional string field.
7. **The sandbox is not a security boundary against hostile code** once `write` or `env` is granted. Use it on projects you trust; the docs say so.

All code below was run in a scratch copy of the repository before this plan was written: it compiles under the strict `tsconfig.json`, the 9 new tests pass, and `deno-integrations` (9), `deno-output` (5), `ts-rails-cli` (11), `ts-rails-regression` (45), `frameworks` (5), `sql-rules` (6) and `oracle-doctor-cli` (1) still pass. The measured table above comes from running the finished code over a snapshot of the private project, whose own working tree stayed clean.

Facts about Deno 2.9.8 that the code depends on (established by running it):

- `deno test --reporter=junit --junit-path=FILE` writes JUnit XML: one `<testcase name classname line col>` per test, `<failure message="…">` for failures (XML-escaped), `<skipped/>` for ignored tests, and `tests="N"` on `<testsuites>`.
- A module that cannot load (missing import, syntax error) aborts the whole run: exit 1, **no report file**, error on stderr. No test files at all: exit 1, `error: No test modules found`, no report.
- Permission refusals surface as `NotCapable: Requires <kind> access to …`; the failure message is the attribute, the XML body holds the stack (not used).
- Deno starts and finds its cache with only the environment variables listed in decision 3.

```ts
// Parser pinned to the JUnit XML of `deno test --reporter=junit` (Deno 2.9.8); it fails closed on any other shape.
export interface JunitCase { file: string; name: string; line: number; status: 'passed' | 'skipped' | 'failed'; message: string }
export type FailureKind = 'permission' | 'environment' | 'assertion';

const ENTITIES: Record<string, string> = { '&quot;': '"', '&apos;': "'", '&lt;': '<', '&gt;': '>', '&amp;': '&' };
const decode = (text: string): string => text.replace(/&(?:quot|apos|lt|gt|amp);/g, entity => ENTITIES[entity] ?? entity);
const attribute = (attributes: string, name: string): string | undefined => new RegExp('\\b' + name + '="([^"]*)"').exec(attributes)?.[1];

export function parseJunit(xml: string): JunitCase[] {
  const declared = /<testsuites\b[^>]*\btests="(\d+)"/.exec(xml)?.[1];
  if (declared === undefined) throw Error('Unexpected deno test JUnit shape');
  const cases: JunitCase[] = [];
  for (const chunk of xml.split(/<testcase\b/).slice(1)) {
    const end = chunk.indexOf('>');
    const attributes = chunk.slice(0, end);
    const name = attribute(attributes, 'name'), file = attribute(attributes, 'classname'), line = Number(attribute(attributes, 'line'));
    if (name === undefined || file === undefined || !Number.isInteger(line)) throw Error('Unexpected deno test JUnit testcase');
    const failure = /<(?:failure|error)\b[^>]*\bmessage="([^"]*)"/.exec(chunk)?.[1];
    cases.push({ file: file.replace(/^\.\//, ''), name: decode(name), line, status: failure !== undefined ? 'failed' : /<skipped\b/.test(chunk) ? 'skipped' : 'passed', message: decode(failure ?? '') });
  }
  if (cases.length !== Number(declared)) throw Error(`deno test JUnit declares ${declared} tests but contains ${cases.length}`);
  return cases;
}

/** permission = the Deno sandbox refused; environment = a native client or service is missing; everything else is an assertion or runtime failure. */
export function classifyFailure(message: string): FailureKind {
  if (/\b(?:NotCapable|PermissionDenied)\b/.test(message)) return 'permission';
  if (/\b(?:NJS|DPI|ORA)-\d+\b|\bE(?:CONNREFUSED|NOTFOUND|AI_AGAIN|TIMEDOUT)\b|Oracle Client/i.test(message)) return 'environment';
  return 'assertion';
}
```

```ts
import fs from 'node:fs';
import os from 'node:os';
import path from 'node:path';
import { pathToFileURL } from 'node:url';
import { spawnSync } from 'node:child_process';
import type { DenoTestAllow, Severity } from '../types/report.js';
import { classifyFailure, parseJunit } from './deno-junit.js';

export interface DenoTestInput {
  dir: string; selected: Set<string>; allow: DenoTestAllow[]; tasks: string[];
  add: (code: string, severity: Severity, file: string, line: number, detail: string) => void;
}
const JUNIT = '.rails-junit.xml';
// Deno's own discovery pattern: *_test.ts, *.test.ts and test.ts (and the mts/tsx variants).
const TEST_FILE = /(?:^|[/_.])test\.(?:m?ts|tsx)$/;
// Network is never granted and there is no way to ask for it; FFI and subprocesses are not offered either.
const FLAGS: Record<DenoTestAllow, string> = { env: '--allow-env', sys: '--allow-sys', write: '--allow-write=.' };
// The child sees only what Deno needs to start: project secrets in the caller's environment stay invisible even with `env`.
const KEEP_ENV = ['PATH', 'Path', 'HOME', 'USERPROFILE', 'LOCALAPPDATA', 'APPDATA', 'SystemRoot', 'SYSTEMROOT', 'TEMP', 'TMP', 'TMPDIR', 'DENO_DIR', 'XDG_CACHE_HOME'];

function clean(message: string, dir: string): string {
  let text = (message.split(/\r?\n/)[0] ?? '').replace(/^Uncaught /, '');
  const redactions: [string, string][] = [[pathToFileURL(dir).href, '<snapshot>'], [dir.replaceAll('\\', '/'), '<snapshot>'], [dir, '<snapshot>'], [os.homedir(), '~']];
  for (const [value, replacement] of redactions) if (value) text = text.split(value).join(replacement);
  return text.replace(/\s+/g, ' ').trim().slice(0, 200);
}

/**
 * Runs the snapshot's tests in a sandbox: read of the snapshot only, network denied, scrubbed environment, no subprocesses, no FFI.
 * Files that a `deno run` task executes are scripts (they may call real systems), not unit tests, and are never run.
 */
export function denoTest(input: DenoTestInput): string {
  const scripts = new Set<string>();
  for (const command of input.tasks) if (/\bdeno\s+run\b/.test(command)) for (const match of command.matchAll(/[\w@./-]+\.(?:m?ts|tsx)\b/g)) scripts.add(match[0].replace(/^\.\//, ''));
  const files = [...input.selected].filter(file => TEST_FILE.test(file)).sort();
  const runnable = files.filter(file => !scripts.has(file));
  const excluded = files.length - runnable.length;
  if (!runnable.length) return 'no test files found' + (excluded ? `; ${excluded} script-like files excluded` : '');
  const env: NodeJS.ProcessEnv = { NO_COLOR: '1', DENO_NO_UPDATE_CHECK: '1' };
  for (const key of KEEP_ENV) if (process.env[key] !== undefined) env[key] = process.env[key];
  const args = ['test', '--no-check', '--reporter=junit', '--junit-path=' + JUNIT, '--deny-net', '--allow-read=.', ...input.allow.map(name => FLAGS[name]), ...runnable];
  const out = spawnSync('deno', args, { cwd: input.dir, env, encoding: 'utf8', shell: false, timeout: 600000, maxBuffer: 16 * 1024 * 1024, windowsHide: true });
  if (out.error || out.signal || out.status === null || out.status > 1) throw Error('deno test did not finish: ' + (out.error?.message ?? out.signal ?? 'exit ' + out.status));
  const report = path.join(input.dir, JUNIT);
  const tail = (out.stderr || out.stdout).trim().split(/\r?\n/).slice(-3).join(' | ');
  if (!fs.existsSync(report)) throw Error('deno test produced no report: ' + tail);
  const cases = parseJunit(fs.readFileSync(report, 'utf8'));
  const count = { passed: 0, skipped: 0, permission: 0, environment: 0, assertion: 0 };
  for (const item of cases) {
    if (item.status !== 'failed') { count[item.status]++; continue; }
    const kind = classifyFailure(item.message);
    count[kind]++;
    input.add('DENO_TEST_FAILURE', kind === 'assertion' ? 'P2' : 'P3', item.file, item.line, `[${kind}] ${item.name}: ${clean(item.message, input.dir)}`);
  }
  const failed = count.permission + count.environment + count.assertion;
  if (out.status === 1 && !failed) throw Error('deno test failed without failing test cases: ' + tail);
  const granted = ['read=snapshot', ...input.allow.map(name => name === 'write' ? 'write=snapshot' : name), 'net denied'].join(', ');
  return `${count.passed} passed, ${failed} failed (${count.permission} permission, ${count.environment} environment, ${count.assertion} assertion), ${count.skipped} skipped; ${excluded} script-like files excluded; ${granted}`;
}
```

````markdown
### deno-test (opt-in)

`--integration deno-test` runs the snapshot's unit tests, which means it runs the project's code; use it on projects you trust. The sandbox is fixed: read of the snapshot only, network always denied, a scrubbed child environment (only the variables Deno needs to start, so secrets in your shell stay invisible even with `env`), no subprocesses and no FFI. `--deno-test-allow env,sys,write` (or `denoTestAllow` in a config file) grants those three one by one; `write` is limited to the snapshot. Files that a `deno.json` task runs with `deno run` are scripts, not tests, and are never executed (they may call real systems).

Each failing test becomes `DENO_TEST_FAILURE` with a class in the detail: `[assertion]` (P2), `[permission]` (the sandbox refused; P3) or `[environment]` (a native client or service is missing, for example `NJS-045` or `DPI-1050`; P3). Messages are cut to one line with the snapshot path and home directory redacted. The integration's `summary` field states the counts, the permissions granted and how many script-like files were excluded. A permission or environment failure is not a project defect: it means the test needs something the sandbox does not grant (subprocesses, FFI, a database), so run it yourself after reading its runner. A module that cannot load aborts Deno's whole run and makes the report `INCOMPLETE`; no test files is a complete empty result. The sandbox is not a security boundary against hostile code once `write` or `env` is granted.
````
