# Import-aware framework and database signals

`tool/src/rules/frameworks.ts` exports `inspectFrameworks(source, compiler, emit)`. It inspects the selected TypeScript AST without importing/executing target code or connecting to a database. All findings are P2, HEURISTIC and inherit the report's source/test/config scope. A finding requests contextual review; it is not proof of exploitation, authorization failure or data loss.

| Code | Evidence required before emitting | Review obligation |
| --- | --- | --- |
| `BETTER_AUTH_SECURITY_DISABLED` | Named alias or namespace access to `betterAuth` imported from `better-auth`/`better-auth/minimal`; literal first-argument object with literal `advanced.disableCSRFCheck: true` or `advanced.disableOriginCheck: true` | Check exact version, deployment path, trusted origins and legitimate isolated tests. The generic `AUTH_SECURITY_DISABLED` syntax lead may also appear; this signal adds imported API context. |
| `DRIZZLE_MUTATION_WITHOUT_WHERE` | Local immutable database created by imported `drizzle` from a `drizzle-orm/` subpath, or that database's direct transaction callback parameter; outermost update/delete call chain contains no visible `where` | Determine whether mutation executes, whether a deliberate whole-table operation is authorized, or whether a wrapper adds predicates. A visible where does not prove tenant/owner authorization or even a nonempty predicate. |
| `DRIZZLE_RAW_REQUEST_SET` | The above Drizzle origin plus `set` receiving direct HTTP JSON or a local const alias: imported Hono Context parameter, direct route callback on an imported Hono instance, or parameter annotated with an unshadowed global Request | Validate unknown data and allowlist mutable fields. Raw object use may mass-assign protected columns; a call named parse is outside this rule's direct-input scope and is not certified as valid validation. |
| `PG_POOL_TRANSACTION` | Local immutable instance of named/aliased `Pool` or default/namespace `pg.Pool` imported from `pg`; `query` receives a literal string/template or literal `{text}` whose initial token is BEGIN | Acquire one client, use it for BEGIN/all statements/COMMIT or ROLLBACK, and release in finally. The lead does not reconstruct a whole transaction or prove a failure occurred. |

Import identity and lexical bindings are tracked locally, including aliases, block/parameter/destructuring shadows, function-scoped var shadows and named function-expression shadows. Type-only imports cannot establish runtime factories. Immutable local aliases are followed with a depth limit; mutable variables, cross-file reexports, dependency injection, user factories and arbitrary control flow remain unevaluated. No name-only assumption that every `db`, `Pool`, `update`, `Request` or `json` belongs to these libraries is made. Unrelated metadata with a security-option-shaped name is not a Better Auth option.

Drizzle emits at most one missing-predicate lead per outer chain; returning/where calls and parenthesized receivers are included. The mutation must start directly on the recognized database/transaction object; unrelated return values such as `db.execute(...).update(...)` are excluded. It does not follow stored mutable query builders across statements or CTE builders such as `db.with(...).update(...)`. Hono inference follows direct constructor/known fluent registration calls, not arbitrary returned objects such as `app.request(...)`. Named imported Context type aliases are supported; arbitrary structural request interfaces and cross-file handler references are not. Request annotations are syntax evidence, not runtime input validation. A custom local Request type suppresses the global-Web-Request path conservatively.

The pg check is a narrow initial-keyword recognition, not a SQL parser: dynamic SQL, SQL beginning with comments, START TRANSACTION, connection reservation elsewhere and subsequent SQL syntax are not analyzed. postgres.js transaction correctness is demonstrated by [real database suites](../examples/data/README.md), not inferred from a method name.

TimescaleDB policy windows, partition keys and retention compatibility are **NOT EVALUATED by these static rules**. This module contains no homemade SQL parser and adds no SQL parser dependency. The exact real-extension cases, including all partition columns in keys and summary loss after refreshing deleted raw windows, are executable in [the data package](../examples/data/README.md). Dynamic SQL, deployed catalog state, raw/aggregate retention, effective roles and runtime costs need actual evidence following [PostgreSQL](postgresql.md) and [TimescaleDB](timescaledb.md).

Version evidence consulted for API meaning: installed Better Auth/core 1.7.25 declarations and [tagged options source](https://github.com/better-auth/better-auth/blob/v1.7.25/packages/core/src/types/init-options.ts); Drizzle 0.45.4 installed declarations and [tagged update builder](https://github.com/drizzle-team/drizzle-orm/blob/0.45.4/drizzle-orm/src/pg-core/query-builders/update.ts); Hono 4.13.19 installed metadata and [tagged Hono constructor/fluent API](https://github.com/honojs/hono/blob/v4.13.19/src/hono-base.ts); pg 8.16.3 metadata/tagged source and [same-client transaction contract](https://node-postgres.com/features/transactions). These sources explain review obligations; the static module does not resolve or certify the audited target's installed versions.

Verification: `npm run build`, then `node --test dist/tool/test/frameworks.test.js`. Tests create real TypeScript compiler ASTs and assert positive and legitimate negative cases, exact finding codes and one-based lines. Additional counterexamples first failed for unrelated nested auth metadata, function/var shadows, destructured factory results, parenthesized safe query chains and unrelated Hono return objects; implementation changes returned them to green.
